## 0. ⚠️ negative プロンプトは使えない

**`/create-tileset` と `/map-objects` には negative 系のパラメータが存在しない**（実仕様で確認済み）。`/create-image-pixflux` には `negative_description` があるが、仕様上 **"(Deprecated)"** と明記されている。

したがって **「fantasy / medieval / RPG を除外する」という指示を API に直接与えることはできない。** 排除は次の4つで行う。**この順で効く。**

| # | 手段 | パラメータ | 効き方 |
| --- | --- | --- | --- |
| **1** | **パレット強制** | `color_image` | **最強。** 64色の褪せた日本の夏の色に縛れば、西洋ファンタジーの華やかな配色は物理的に出せない |
| **2** | **輪郭を消す** | `outline: lineless` | RPG スプライト特有の黒縁が消える。本作の「輪郭線は使わない」規約とも一致 |
| **3** | **密度を落とす** | `detail: low detail` / `medium detail` | 装飾過多を防ぐ。本作は余白と単調さが不安を作る |
| **4** | **記述の具体性** | `description` / `text_guidance_scale` | 「石造りの建物」ではなく「モルタル二階建て、トタン屋根、室外機」と書く。抽象的に書くほどファンタジーへ流れる |

`text_guidance_scale` は既定 8.0。**本作は 9.0〜10.0 を基準**にし、記述への忠実度を上げる。

## 1. 光と影の扱い

参考資料14点の測定に基づく（根拠は [`../palettes/PALETTE_ANALYSIS.md`](../palettes/PALETTE_ANALYSIS.md)）。

### 数値の基準

| 指標 | 値 |
| --- | --- |
| 明度比（光÷影） | **8:1** |
| 光と影の色相差 | **30〜40度**（レジームによる。下記） |
| 影の彩度 ÷ 光の彩度 | **1.8** |

### 最重要の原則 — 影が色を持つ

**光を受けた面は彩度が低く（白へ抜ける）、影が彩度を持つ。**

これは直感と逆だが意味は明快である。光源そのものは高彩度だが、**光を受けた面は白へ飽和して彩度を失う**。一方で影は環境光の色に染まる。

> **藍も墨も「濃い灰色」ではなく「濃い色」である。**

暗部を無彩色（`ink`）だけで作らない。`indigo` や `concrete` の暗段を使う。

### ★ 照明レジームの3分類

**場面によって光と影の色相関係が反転する。** どのフィールドがどれに属するかを把握してから描く。

#### レジーム A — 暖色光 × 寒色影（色相差 162〜175度）

**該当**：F01 国道沿道、F05 旧街道商店街、F12 木平団地、F13 倉ノ前NT

ナトリウム灯や窓の白熱光が、藍の闇に落ちる。**本作で最もコントラストが強い条件。**

- 光源 … `sodium` / `bulb`
- 光を受けた面 … `earth` の中〜明段（暖色側へ寄せる）
- 影 … `indigo` の暗段
- **光の届く範囲を狭く取る。** 光溜まりの外は一気に藍へ落とす

#### レジーム B — 寒色光 × 寒色影（色相差 14〜26度）★最も難しい

**該当**：F03 高架下、F06 市民センター、F01 のコンビニ前

自販機・蛍光灯・LED が、藍の闇に落ちる。**光も影も寒色なので、色相では分離できない。**

> **ここでは明度と彩度だけで光と影を分ける。**

- 光源そのもの … `vending[1]` `fluoro[1]`（高彩度・高明度）
- **光を受けた面** … `concrete` か `green` の**中段**。**光源色をそのまま地面に置かない**
- 影 … `indigo` の暗段
- **明度差を A より大きく取る。** 色相が助けてくれない分、明度で稼ぐ

**このレジームの成否が本作の夜景を決める。**

#### レジーム C — 自然光（暖）× 暖色影（色相差 28度）

**該当**：F04 谷戸、F07 光明院、F08 天神社、F16 薬師谷、および全フィールドの昼

太陽光と木漏れ日。**コントラストが最も低い。**

- 光 … `earth` / `green` の明段
- 影 … 同系統の暗段（**別系統へ移らない**）
- **色相差に頼らず、明度段の差だけで形を取る**

## 2. 視点と投影 — 真上見下ろしで高さをどう表現するか

**視点は真上に近い見下ろし（`view: high top-down`）。斜め見下ろしにしない。**

### 建物の高さ

真上から見ると、建物は**屋根**として見える。壁はほとんど見えない。

| 要素 | 表現 |
| --- | --- |
| 屋根 | 面積の大半。瓦・トタン・陸屋根の質感で建物の種類を示す |
| 壁 | **手前側（南側）だけ**わずかに見せる。1〜2タイル分 |
| 高さの表現 | **壁の露出量ではなく、落ち影の長さで示す** |
| 庇・軒 | overhead レイヤーに置き、プレイヤーの上に重ねる |

> **高さは「見せる」のではなく「影で示す」。**
> 真上見下ろしで壁を多く見せると、視点が斜めに崩れる。

### 建物をどう分解するか — **未決。パイロットで決める**

- **案A**：`/map-objects` で建物1棟を1枚のスプライト（最大256px）として作る
- **案B**：屋根タイル＋壁タイル＋ドアオブジェクトに分解し、タイルで組む

`obj_civic_facade` のパイロットで判断する。**F02 / F05 / F11 / F12 / F13 の建物すべてに波及する**ため、結論を必ず出してここに追記する。

## 3. 32pxグリッドの描き込み密度

| 対象 | 密度 | `detail` |
| --- | --- | --- |
| 地面タイル（ground） | **低い。** 1タイルに主要素1つ。継ぎ目を目立たせない | `low detail` |
| 単体オブジェクト（objects） | 中。識別できる最小限の特徴だけ | `medium detail` |
| overhead | **最も低い。** シルエットが読めれば足りる | `low detail` |
| UI・アイコン | 中〜高。小さいので情報密度が要る | `medium detail` |

**原則：ディテールを詰め込みすぎないこと。余白と単調さが不安を作る。**

32px に描けるのは**3〜4段の明度差まで**。それ以上は潰れる。
1タイルに使う色は **8色以内**を目安にする。

## 4. 影の付け方

| 項目 | 規則 |
| --- | --- |
| 光源の方向 | **昼は南上方から**（画面上が北）。落ち影は**下方向（南へ）**に伸びる |
| 夜 | 光源は画面内の点光源。**落ち影は光源から放射方向** |
| 影の色 | **黒を混ぜない。** `indigo` か `concrete` の暗段に置き換える |
| 落ち影の長さ | 昼は物体の高さの 0.5倍、夕は 1.5倍、夜は光源との距離による |
| 接地影 | **必ず入れる。** 無いとオブジェクトが浮く。1〜2px の暗い縁 |
| 影のエッジ | **硬く。** ぼかさない。アンチエイリアスをかけない |

ノーマルマップによる陰影は Godot 側で乗る。**素材に描く影は「落ち影」と「接地影」だけ**にし、面の陰影はノーマルマップに任せる。

## 5. 時間帯別の色調変化

**素材を時間帯ごとに作らない。** 確定した64色パレット内での色置換で作る。
置換テーブルは [`../palettes/palette_spec.yaml`](../palettes/palette_spec.yaml) の `time_variants`。

| 時間帯 | 置換 | 識別できる色数（地の色52中） |
| --- | --- | ---: |
| 昼 | 基準 | 52 |
| 朝 | 各系統 +1段 | 47 |
| 夕 | 各系統 -1段 | 49 |
| 夜 | 各系統 -2段（`earth` のみ -3） | **38** |

**光源色12色は時間帯で変化しない。** 夜に光源だけが色を持って残る。

素材を作るときは**常に「昼」で作る**。夜版は後処理で自動生成される。

## 6. やってはいけないこと

### 描画

- **輪郭線を使わない。** 色面で形を取る（`outline: lineless`）
- **アンチエイリアスをかけない。** 透明度の中間値を作らない（アルファは 0 か 255 のみ）
- **パレット外の色を使わない。** 64色すべて `iwato_64.gpl` から取る
- **斜め見下ろしにしない。** 真上に近い見下ろしを保つ
- **被写界深度・ティルトシフトを表現しない**
- **ディテールを詰め込まない**

### 意匠

- **西洋ファンタジー的意匠を混ぜない。** 石造アーチ、木骨造、樽、松明、剣、紋章
- **RPG的意匠を混ぜない。** 宝箱、看板の羊皮紙、装飾枠
- **「HD-2D」「2D-HD」という語を使わない。** 他社の登録商標である。本作の画風は**「高精細2Dドット絵」**と呼ぶ
- **参考画像を複製しない。** 特定のタイル・建物・キャラクターを写し取らない
- **プロンプトに作品名・キャラクター名・スタジオ名を含めない**

### ホラーの記号

- **血、内臓、不気味な顔を描かない**
- **死の場面、遺体、その痕跡を描かない**
- **自死の方法・手段を、具体的にも暗示的にも描かない。** それを想起させる器具・物体・状態を素材にしない。**プロンプトにそうした語を入れない**
- **暴力・傷を想起させる素材を作らない**

> **普通の風景が、普通であることによって怖い状態を目指す。**
> 見せないことが最も怖い。この制約は演出上の妥協ではなく、優れたホラーの条件である。

フィールドごとの個別制約は [`../requirements/fields.json`](../requirements/fields.json) の `content_constraints` にある。**プロンプト生成時に必ず参照すること。**

**必ず現代（201X年頃）の日本の地方都市として生成する。**

プロンプトには `modern rural Japan` 系の語を含める。negative が使えないため、**肯定側の具体性で殴る**しかない。

- 防音壁、高架、法面、隧道
- 自転車、置き傘、鉢植え、洗濯物、室外機

## 8. パイロットで結論を出す3点

**この3点は未決である。パイロットの結果をここに追記して確定させる。**

### ① 自販機の光が地面に落ちる部分に、どの色を使うか

`vending[1]` (`#4DC7AE`, 彩度0.52) は他の63色から完全に浮く。それは**光源そのもの**としては意図どおりである。

しかし **その光が周囲の地面を照らす部分に何を使うか**が未定である。`vending[1]` をそのまま地面に置くと明るすぎるはずで、実際には `concrete` `green` `fluoro` の中間段のいずれかになる。

**`obj_vending_machine` のパイロットで確認する。** 「光源そのものの色」と「光を受けた面の色」の使い分けが本作の夜景の成否を決める。**レジーム B の中心問題**でもある。

### ② 夜の38色で、常時暗いフィールドが成立するか

夜の置換で地の色52色のうち14色が潰れ、**実質38色**になる。F03（隧道）や F16（禁域）のような**常時暗いフィールドで使える色が38色**ということである。

**`tile_concrete_slab` のパイロットで確認する。** 足りなければ `palette_spec.yaml` のランプ段数か gamma を調整する。**パレットは spec から再生成できる。**

### ③ 建物をどう分解するか

第2節を参照。`obj_civic_facade` のパイロットで判断する。
