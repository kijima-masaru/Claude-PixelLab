# パイロットで判明したこと

2026-09-04、F06 パイロットで **15 generations**（残高 1,985 / 2,000）を使って得た知見。
**量産に入る前にこれを読むこと。** 知らずに進むと作り直しになる。

すべて実測に基づく。推測は「未検証」と明記してある。

---

## 1. ★ エンドポイントによって投影が違う

**これが最大の発見であり、10 generations の最大の成果である。**

| エンドポイント | 出力される投影 | 本作（真上見下ろし）との適合 |
| --- | --- | :--: |
| `POST /create-tileset` | **正射影の真上見下ろし** | ✅ |
| `POST /map-objects` | **アイソメトリック**（斜め見下ろし） | ❌ |
| `POST /create-image-pixflux` | **正面立面**（`isometric: false` でも） | ❌ |

### 実測の内容

3エンドポイントすべてに `view: "high top-down"` を送った。ログで送信を確認済み。

- `/create-tileset` … 道路タイルが完全な平面で出力された
- `/map-objects` … 橋脚・自販機・建物の**3点すべてがアイソメトリック**。建物は壁2面と屋根が斜めに見える教科書的なアイソメ
- `/create-image-pixflux` … `isometric: false` を明示しても**正面立面**になった。さらに質が落ち、指示していない木と岩まで生成された

### 原因

`view` の選択肢は3エンドポイントとも `low top-down` / `high top-down` / `side` のみで、
**真の正射影を指定する手段がない。** `high top-down` は「高い角度の俯瞰」であって
「真上」ではない。`isometric: false` は「アイソメにしない」だけで
「真上から見る」を意味しない。

### したがって

> **PixelLab で真上見下ろしを出せるのは `/create-tileset` だけである。**

**投影の問題は「高さのある物」にだけ起きる。** 地面に貼る平坦な物
（側溝の蓋、白線、マンホール）は、真上から見てもアイソメで見ても
ほとんど同じ形になるため、`/map-objects` で作れる。

## 2. ★ タイルセットに書いた特徴は、全16タイルに複製される

`/create-tileset` は**均質な素材**を生成する仕組みである。
記述に「たまにある物」を書くと、**16タイル全部にそれが入る。**

### 実測の内容

`lower_description` に「faded white painted line」、
`upper_description` に「steel grating drain cover」と書いたところ、

- 白線が**16タイル全部**に入り、敷き詰めると画面全体に縞が走った
- 歩道**全体**がグレーチング（縦縞のパネル）になった

### したがって

> **タイルセットの記述には「均質な素材」だけを書く。**
> 白線・グレーチング・マンホール・路面標示は**素材ではなく特徴**であり、
> 別の素材として作って地面に重ねる。

これは全タイルセットに対して点検すること。1本でも特徴を含んでいると、
そのフィールド全体に縞や模様が反復する。

---

## 3. ★ 共通プレフィックスは素材の記述を希釈する

### 実測の内容

`lower` と `upper` の両方に100文字超の共通プレフィックスを付けて送ったところ、
API が返したタイルセット名がこうなった。

```
"pixel art for a top-down game, modern rural Japan ↗ pixel art for a top-down game, modern rural Japan"
```

**lower と upper の名前が同一になっている。** API から見て2つの地形が
区別できておらず、素材を指す語が末尾に埋もれていた。
結果、`lower`（アスファルト）が**単一色で塗りつぶされた**（使用色数1）。

共通プレフィックスを外し、記述を425文字から89文字に縮めたところ、
**同じ `lower` が7色のテクスチャを持つようになった。**

### したがって

> **`/create-tileset` の記述には素材の語だけを置く。**
> 画風は `color_image` と `outline` / `shading` / `detail` が担保している。
> 記述で画風を指定しようとすると、素材の記述が薄まる。

## 4. ★ `color_image` によるパレット強制は完全に機能する

**5回の生成すべてで、パレット外の色は0色だった。**

| 生成 | 使用色数 | パレット外 |
| --- | ---: | ---: |
| タイルセット 1回目（16タイル） | 41 | **0** |
| タイルセット 2回目（16タイル） | — | **0** |
| 橋脚 | 28 | **0** |
| 自販機 | 43 | **0** |
| 建物 | 33 | **0** |

後処理（パレット吸着）は**画素レベルで0変化**だった。生成の時点で既に
パレットに収まっており、後処理は実質的な無変換だった。

### したがって

> **negative プロンプトが使えない問題は、パレット強制で解決している。**
> 除外を言葉で指定するのではなく、**出せる色を制限する**という構造的な解決になっている。
> 西洋ファンタジーの華やかな配色は、64色の褪せた色に縛れば物理的に出せない。

**`color_image` は 64×64 でなければならない。** 8×8 で送ると
`Expected image of size 64x64` で生成が失敗する（仕様に記載なし。実測で判明）。
失敗したジョブは課金されない。

## 5. ★ 暗さと受光面は、スプライトに焼き込まない

### 実測の内容

橋脚に「deep shadow with almost no light」と指示したが、**暗くならなかった**
（明度30以下の画素が26%しかなく、上部に電球色まで乗った）。

自販機に「the glow spilling onto the asphalt around its base」と指示したが、
**光が地面に落ちる部分は生成されなかった。** `/map-objects` は透過背景の
単体オブジェクトを作るため、**そもそも地面が存在しない。**

### したがって

> **`/map-objects` は物体を中立的な照明で描く。** マップに置く素材として当然の設計であり、
> 暗さを指示するのは道具と喧嘩している。
>
> **暗さも受光面も、Godot の 2Dライトで実行時に作る。**
> パレットの暗部はタイルマップと実行時ライティングで使われる。

これは素材点数を増やさずに解決する。自販機の光溜まりは `PointLight2D` が作る。

### 副次的な結論 — 接地影も同じ

パイロットの建物には、アイソメ前提の長い接地影が右下に焼き込まれていた。
真上見下ろしでは意味を持たない。

> **接地影もスプライトに焼き込まない。Godot 側で実行時に落とす。**
> 「暗さは実行時に作る」という結論と整合させる。
>
> ただし**接地影は「そこに物がある」ことを示す最小限の手がかり**でもあるため、
> 1〜2px の接地部分だけは素材に描く。長く伸びる落ち影は実行時に任せる。

## 6. ★ 肯定文の中の "no visible texture" は、negative の代わりに実際に効く

negative パラメータは使えない（第4節）。しかし**肯定文の末尾に置いた否定句は効く。**

### 実測の内容

4回目と5回目で `lower` の記述だけが違い、他の条件（shading / detail /
color_image / guidance / outline）は完全に同一だった。

| | `lower` の記述 | ざらつき | 周期性 |
| --- | --- | ---: | ---: |
| 4回目 | `a smooth uniform dark grey asphalt road surface, featureless and matte, **no visible texture or markings**` | **0.9** | 0.85 |
| 5回目 | `smooth uniform dark grey asphalt, matte and featureless` | 4.0 | 0.98 |
| 6回目 | 4回目と**一字一句同じ**に戻した | **0.87** | 0.87 |

**この句を落とすとざらつきが4倍以上になり、戻すと再現した。** 偶然ではない。

> **⚠️ 訂正（2026-09-04）。4回目は「成功」ではなかった。**
> 当時これを成功と判定したが、**比較対象が実写写真であり、尺度を揃えていなかった。**
> 依頼者の自作ゲーム画面を同一条件（70px→32px 縮小）で測ると、
> 地面のざらつきは**日向で 12〜15、深い影で 2.4〜3.6** である。
> 4回目の 0.92 は、**光の当たった地面の 13分の1 しかない。**
> この句が効くという発見自体は正しいが、**4回目を到達点として扱ってはならない。**
> 詳細は第11節。

### したがって

> **`no visible <特徴>` を description の末尾に置く。** これが本環境における
> negative プロンプトの代替である。`featureless` や `plain` といった
> 形容詞だけでは足りない。**「何を出すな」を名指しする必要がある。**

平坦な面を作る全ての素材（asphalt / concrete / tarmac_parking）の統制語彙に
この句を入れてある。**短くしようとして削らないこと。**

## 7. ★ 語の含意が、指示より強く形を決める

### 実測の内容

4回目は `lower`（アスファルト）が成功し、`upper`（歩道）が失敗した。
**両方に同じ `featureless` を指示していたにもかかわらず**である。

原因は `sidewalk` という語だった。この語は「敷石やタイルで舗装されている」
という**構造の含意**を持ち、`featureless` という指示より強く働いた。
結果、歩道は**レンガ壁**になった。

5回目で `sidewalk` を外して `concrete raised edge` にしたところ、
レンガ壁は**正方格子**に変わった。構造の種類は変わったが、消えはしなかった。

### したがって

> **統制語彙には「素材」だけを置き、「物」を置かない。**
> `sidewalk` / `parking lot` / `rice paddy` / `foundation blocks` /
> `painted line` は物であり、それぞれ固有の構造を連れてくる。

`fields.json` の `terrain_vocabulary` 全29語を点検し、不規則14本に属する
10語から含意を外した。`painted_line` は素材ではなく特徴なので削除した。
**規則15本の5語（tatami / floorboards / steps / flagstone / blocks）は、
その構造こそが目的なのでそのままにしてある。**

## 8. ★★ 同一平面上の2素材は成立しない。upper は必ず構造を持つ

**これは仕組みの制約であり、プロンプトでは解決できない。**

### 実測の内容

`upper` の周期性は、記述を何に変えても動かなかった。

| 回 | `upper` の記述 | ざらつき | 周期性 |
| --- | --- | ---: | ---: |
| 3回目 | concrete sidewalk | 17.1 | 0.99 |
| 4回目 | pale concrete, plainly lighter | 8.2 | **1.00** |
| 5回目 | pale concrete raised edge, plain | 7.8 | **1.00** |

一方 `lower` は条件次第で 0.9 まで平坦にできた。**この非対称が本質である。**

`/create-tileset` は高低差モデルであり、`upper` は「lower の上に乗った物」
として描かれる。**上に乗っている以上、必ず単位に分割され、縁を持つ。**

### 回避策 — upper を lower のほぼ同一バリエーションにする

6回目で、`upper` を**別素材にするのをやめ**、`lower` と語順・語彙まで揃えて
**色の語1つだけ**を変えた（`dark grey` → `slightly lighter grey`）。

| | ざらつき | 周期性 |
| --- | ---: | ---: |
| 4回目 upper（別素材） | 8.21 | 1.00 |
| **6回目 upper（ほぼ同一素材）** | **0.53** | **0.66** |

**格子は消えた。** 分類Bの床タイル（ほぼ同一2素材の組）で採った設計が、
不規則な地形にもそのまま使えることを意味する。

> **不規則な地形は「路面×歩道」のような異素材の組で作らない。**
> 1素材につき1本のタイルセットを、**濃淡だけが違う2素材の組**で作る。
> 素材の境界（縁石・路肩）は `ground_detail` のデカールで処理する。

## 9. ★ upper の周囲に錆色の縁が描かれる。後処理で除去できる

### 実測の内容

6回目で構造は消えたが、**`upper` の領域の外周に暖色（H 20〜36°）の
点線状の縁**が描かれた。全16タイルで 920 px、5.6% を占める。

これは第「その他」節の **`outline: lineless` が無視される**現象の別の現れである。
問題は、この縁が**タイルの左右端にも描かれる**ことで、
連続した歩道の内部に**32px 周期の縦縞**が現れてしまう点にある。

パレット外ではない（地の52色に収まっており、光源色でもない）。
**色の逸脱ではなく、線が引かれているという構造の問題である。**

### 後処理で消える

暖色の画素のうち、**近傍3pxに lower（暗い面）が無いもの**＝地形の境界ではなく
タイル内部の筋であるものだけを、周囲の最頻色で埋める。

| | ざらつき | 周期性 |
| --- | ---: | ---: |
| 6回目 upper 生 | 0.53 | 0.66 |
| **6回目 upper 後処理後** | **0.41** | **0.76** |

560 px を内部の筋として消し、360 px を地形の境界として残した。
**境界の縁は残す。** 路面と歩道の境目には線があるべきだからである。

> **これは既存のパレット吸着とは別種の後処理である。**
> 色を寄せるのではなく、**画素を消して埋める**。採用するなら
> `tools/postprocess.py` に独立した工程として実装すること。

## 10. ★★★ タイルセットは1素材だけを作る。特徴は別のレイヤーへ出す

**路面と瓦という正反対の素材で、独立に同じ結論へ到達した。**
偶然ではなく、`/create-tileset` という道具の性質である。**設計原則として確立する。**

### 到達の経路

| | やろうとしたこと | 起きたこと |
| --- | --- | --- |
| 不規則（路面） | `lower`=アスファルト × `upper`=歩道 | `upper` がレンガ壁・正方格子になった。周期性 1.00 が3回続き、記述を変えても動かなかった（第8節） |
| 規則（瓦屋根） | `lower`=瓦の面 × `upper`=棟 | **棟が面いっぱいに反復し、機械のパネルになった**（第2節の再演） |

前者は「異素材の組」の失敗、後者は「線状の特徴を面に置いた」失敗である。
**表面上は別の失敗だが、原因は同じ。**

> `/create-tileset` の2つのスロットは、**どちらも「面を埋める均質な素材」しか受け付けない。**
> `upper` は「lower とは別の物」ではなく「lower の隣に広がる別の面」である。

### したがって — 3つの規則

1. **1本のタイルセットには1素材だけを入れる。**
   `lower` と `upper` は**濃淡だけが違う同一素材の組**にする。
   6回目で、これだけで `upper` のざらつきが 8.21 → 0.53 に落ちた。

2. **「面ではないもの」は地形スロットに入れない。**
   判断軸は高低差の有無ではなく、**面か線か・素材か特徴か**である。
   - 線／特徴の例: 縁石・白線・グレーチング・マンホール・**棟**・軒・樋・鬼瓦
   - これらを `upper` に書くと、面いっぱいに反復する

3. **外した特徴は、別のレイヤーで作る。**

   | 特徴 | 行き先 | エンドポイント |
   | --- | --- | --- |
   | 白線・マンホール・側溝の蓋・グレーチング | `ground_detail` | `/map-objects`（deco） |
   | 縁石・路肩・素材の境目 | `ground_detail` | `/map-objects`（deco） |
   | 棟・鬼瓦・軒・樋 | `objects` | `/map-objects` |

### この原則が及ぶ範囲

- 不規則14本 … すべて「1素材＋濃淡」に組み替える
- 規則15本 … 同上。瓦・板張り・畳の**素材の反復は残す**（それは面の性質であって特徴ではない）
- 屋根5本 … 棟を外し、屋根面だけのタイルセットにする
- `deco` の点数が増える。**これは設計の劣化ではない。**
  タイルセットに焼き込めば全16タイルに反復し、フィールド全体が壁紙になる（第2節）。
  デカールとして置けば「たまにある」を表現できる。**むしろ正しい分解である。**

## 11. ★★ 目標値は「依頼者の自作ゲーム」から取る。ただし画面の測定値をそのまま使わない

**条件を揃えずに比較していた誤りが2つあった。** 記録に残す。

| 誤り | 何が起きたか |
| --- | --- |
| **尺度を揃えなかった** | 1265px のフルカラー描画と 32px のタイルを原寸で比べていた。まず同じ物理スケールへ揃える |
| **光の条件を揃えなかった** | 最初に測った「自作 3.81」は**深い影の部分**だった。同じ地面でも日向は 12〜15 ある |

### 同一条件での実測（70×70 → 32×32 LANCZOS、吸着なし）

| 対象 | 平均明度 | ざらつき | 周期性 |
| --- | ---: | ---: | ---: |
| 自作 地面（日向） | 75〜90 | **12.2 / 14.7 / 12.6** | 0.63〜0.69 |
| 自作 地面（影） | 33.0 | 3.56 | 0.61 |
| 自作 地面（深い影） | 19.2 | 2.42 | 0.81 |

### ⚠️ しかし、この 12〜15 を目標にしてはならない

**画面の測定値には、3Dのライティングと法線の陰影が含まれている。**
テクスチャだけを切り出して等倍でタイルに焼くと、**迷彩柄になる**（実測）。
画面で自然に見えるのは、光・影・上に乗った物と一緒に見ているからである。

コントラストを落として目視で確かめたところ、こうなった。

| コントラスト | ざらつき | 見え方 |
| ---: | ---: | --- |
| ×1.00 | 12.5 | **迷彩。路面に見えない** |
| ×0.70 | 7.9 | まだ騒がしい |
| **×0.50** | **6.8** | **路面に見える。最良** |
| ×0.35 | 6.4 | 平坦に寄りすぎ |

> **焼き込むタイルの目標は ざらつき 5〜7、周期性 0.65 前後。**
> 画面から測った 12〜15 は「光込みの見え方」であって、素材の目標ではない。

### 過去7回の並べ直し

| 回 | ざらつき | 判定 |
| --- | ---: | --- |
| 3回目（レンガ壁） | 9.3 | **やはり過剰**。量も形も外していた |
| 4回目（当時「成功」と判定） | 0.92 | **目標の7分の1。全く足りていない** |
| 6回目 | 0.87 | 同上 |
| 7回目 瓦 lower | 0.77 | 同上 |

**4回目を「成功」と判定したのは誤りだった。** 実写写真と尺度を揃えずに比べていた。
**7回とも目標帯（5〜7）に一度も入っていない。**

## 12. ★ パレット吸着の色距離は CIE Lab で測る

`tools/lib/imageops.py` の `_nearest()` は重み付き RGB（`2R²+4G²+3B²`）を使っている。
**この距離は、中性の灰色を紫ランプへ吸着させる。**

### 実測（自作ゲームの舗装 32×32 を地の52色へ吸着し、吸着先の系統を数えた）

| 色距離 | 中性 | 藍 | **紫** |
| --- | ---: | ---: | ---: |
| 元画像（吸着前） | 78.6% | 7.4% | 14.0% |
| **重み付き RGB（現行実装）** | 73.5% | 20.3% | **6.1%** |
| 素の RGB | 81.0% | 18.9% | 0% |
| **CIE Lab** | **78.7%** | 21.3% | **0%** |

**CIE Lab が元画像の分布を最もよく保つ。** 現行実装だけが紫を残す。

これまで表面化しなかったのは、**生成物が最初からパレット内に収まっており、
後処理が画素レベルで無変換だったため**である（第4節）。
**パレット外の画像を吸着させた瞬間に問題になる。**

> `_nearest()` を CIE Lab に置き換えること。**未実施。** 挙動が変わるため承認を待つ。

## 13. ★★★ 手続き的生成は、タイルセットにおいて生成 API より優る

**継ぎ目が原理的に生じない。** これが決定的な違いである。

| | 生成 API | 自作画像の切り出し | **手続き的生成** |
| --- | --- | --- | --- |
| 継ぎ目 | 16枚が繋がる（実証済み） | **端が合わない。** ランダム配置で誤魔化す | **トーラス上で生成するため原理的に生じない** |
| 反復 | 1タイルの反復＝壁紙 | 12変種のランダム配置で回避 | **256px=64枚が互いに繋がる。周期は8m** |
| 素材の入手 | 記述で頼む。**7回とも外した** | 画面に映っているものだけ。1画面で 5/27 | **どの素材でも作れる** |
| 失敗の費用 | 3 generations / 回 | 0 | **0** |
| 制御 | 言葉。再現性なし（seed は非決定論的） | パラメータ | **パラメータ。完全に再現する** |
| 規則的な素材 | 歪む | 画面に無ければ不可 | **格子を正確に描ける** |

### 原始関数は4つで足りる

`tools/lib/procgen.py`。**すべてトーラス上で閉じている**（2x2 に並べて
継ぎ目が出ないことを実測で確認済み）。

| 関数 | 作るもの | 使う素材 |
| --- | --- | --- |
| `fbm` | 大きく低コントラストな斑 | 土・草・水・コンクリート |
| `voronoi` | 不規則な区画 | 石畳・砂利・礫・崩れた礎石 |
| `grid` / `waves` | 規則的な格子と正弦波 | 畳・板張り・トタン・法枠 |
| `strokes` | 短い線の散布 | 草・落ち葉・杉の針葉・木目 |

**`voronoi` は F2 − F1（次近傍と最近傍の距離差）で測ること。**
単純な F1 は区画の中心からの距離になり、目地が引けない。

**`grid` / `waves` の pitch は面の一辺を割り切る値にすること。**
そうでないと周期境界で格子がずれ、継ぎ目に段差が出る。

### 斑の大きさを決めるのは `base_cells`

256px の面での実測。

| `base_cells` | ざらつき | 見え方 |
| ---: | ---: | --- |
| 4 | 1.6 | 雲のよう。大きすぎる |
| 8 | 2.5 | 目標帯を下回る |
| **16** | **3.7〜4.7** | **目標帯（3.5〜6.0）の内側** |

### 未解決 — 絵作り

**構造は解決したが、色は未調整である。** 初回の試作は迷彩服に見えた。
緑の彩度が高く、土の斑が強すぎたため。**これはパレットの範囲を
切って解く**（`procgen.ramp` の `lo` / `hi`）。

> **鮮やかな色を「使わない」のではなく、「取り出さない」。**
> ランプの下半分しか渡さなければ、鮮やかな緑は物理的に出せない。
> 第4節の `color_image` によるパレット強制と同じ考え方である。

## 14. ★★★ 色相を混ぜない。質感はコントラストと斑の細かさで出す

**迷彩とは「異なる色相の斑が同程度の面積で散らばっている状態」そのものである。**
色を褪せさせても、複数の色相が同じ強さで混在する限り迷彩からは抜けられない。

パレットに色相の穴があった（第13節の後日談・olive/warm を追加）あとも、
**新旧の系統を混ぜた12案はすべて迷彩に見えた。** 解は配合ではなく構造だった。

### 実測 — 差し色は面積を絞っても効かない

主系統1つ（olive 6段）に、差し色（最暗の土 `#291616`）を面積比を変えて混ぜた。

| 差し色の面積 | 見え方 |
| ---: | --- |
| **0%** | **一つの表面に見える。光と影がある** |
| 12% | 穴か焦げ跡に見える |
| 22% | 同上 |
| 35% | 同上 |

暗部にだけ差しても、明部にだけ差しても、結果は変わらなかった。

> **面積だけを絞っても効かない。明度を見落としていた。**
> **差し色は「明度が近く、色相だけが違う」色でなければ、
> 素材の斑ではなく穴になる。**

### そして差し色は要らなかった

色相を1つに固定したまま、**コントラストと斑の細かさだけ**を上げると、
目標帯に届いた。

| | コントラスト | オクターブ | `base_cells` | ざらつき |
| --- | ---: | ---: | ---: | ---: |
| A | 0.70 | 4 | 16 | 1.48 |
| B | 1.00 | 4 | 16 | 2.40 |
| C | 1.00 | 5 | 16 | 2.25 |
| **D** | **1.30** | **5** | **24** | **3.96** ✓ |

**色相は1つ。それでも質感が出る。**

### したがって — 残り19本すべてに効く原則

> **1つの素材は1つの色相で作る。** 階調は明度差で作る。
> 質感が足りなければ**コントラストと斑の細かさ**を上げる。
> **色相を足して質感を補おうとしてはならない。** 迷彩になる。

`tile_asphalt_curb` が成功したのも同じ理由である。9色を使っていたが、
**色相は狭かった。**

### 副産物 — 周期性の指標は、この作り方には当てはまらない

従来の周期性は「1枚のタイルを自分自身で反復したときの目立ちやすさ」を測る。
手続き的生成では 256px のトーラス面から64枚を切り出すため、
**反復の周期は32pxではなく8タイル（8m）である。**
32px の切片を測っても実際の見え方と対応しない。指標を作り直すこと。

## 15. ★★ 系統を色相だけで選んではならない。**彩度の下限が要る**

タイルセット21本を量産する過程で見つけた。**17本すべてに影響し得た欠陥である。**

### 彩度 0.05 を下回る色は、色相が定まらない

`green` を「色相 95〜180度」だけで選んでいたところ、**ほぼ白の
`#EFF0F0`（彩度0.03）が「緑」として拾われていた。** その結果:

    緑ランプの明度 49.5 〜 239.5、平均段差 31.7
    → **ざらつきが目標帯（3.5〜6.0）を突き抜ける**

段差の大きいランプでは、ノイズが隣接2段を行き来するだけで
ざらつきが上がる。**コントラストでは下げられない。**

> **系統は (色相の範囲, 彩度の上限, 彩度の下限) の3つで選ぶ。**

### 中性は「寒色の灰」と「暖色の灰」に分ける

「彩度の低い色すべて」を中性としていたため、青灰（H205〜225）と
暖灰（H30〜35、`warm` ランプ）が同じ系統に入り、
**色相の広がりが 175度**になっていた。`warm` を足した意味が失われる。

    concrete … 色相 195〜250、彩度 0.22 以下。石・コンクリート・アスファルト
    warm     … 色相  20〜 50、彩度 0.16 以下。**踏み固められた土・埃・褪せた木部**

### 色相帯の窓は、ランプのドリフトを含めて切る

`green` ランプは spec 上 色相 198→104 とドリフトする。窓を 95〜180 に
していたため**暗端（色相198度付近）が落ち、鮮やかな明部しか残らなかった。**
窓は 95〜200 に広げた。

### 素材の色は、明度の範囲と bias で決める

パレットを変えずに絵作りを直せる。実際に効いた例:

| 症状 | 直し方 |
| --- | --- |
| 杉の落ち葉・板張りが赤すぎる | `earth`（H0〜45・彩度0.30〜0.39）ではなく **`warm`** を使う。明度をいくら下げても赤味は抜けない |
| 苔・下草・芝が鮮やかすぎる | `green` の明部を使わない。芝と法面は **`olive`** へ |
| 石が明るく藤色に寄る | `concrete` の範囲を 0.05〜0.5 に切る |
| 水面が黒すぎる | `indigo` の範囲を 0.25〜0.8 へ上げる |
| 目地が白く目立つ | **目地は暗い。** 明るく描くと「線」として主張しすぎる |

**色相を変えたいときは系統を変える。明度を変えたいときは範囲と bias を変える。**
この2つを取り違えると、いくら調整しても直らない。

## 16. ★ 反復の指標は、素材の異方性と切り分ける

`grid_visibility` の生の値は、**縞模様の素材で 0.65〜0.87 になる。**
しかしそれはタイルの継ぎ目ではなく、**素材そのものの異方性**である。
縞は繊維の方向にずらしても同じに見える。トタン屋根も板張りも、
現実にそうである。

| 素材 | 格子に乗る32pxずらし | 乗らない33pxずらし | 差 |
| --- | ---: | ---: | ---: |
| トタン屋根 | 0.888 | 0.859 | **0.029** |
| 板張りの廊下 | 0.763 | 0.754 | **0.009** |
| 枯れ草（比較） | 0.012 | 0.013 | −0.001 |

> **格子に乗るずらしと、乗らないずらしの差を見る。**
> 異方性は両方に等しく出るため相殺され、タイル由来の成分だけが残る。

実装上の注意が2つある。

1. **ずらしの差は 1px でなければならない。** 5px にすると素材そのものの
   相関まで変わり、縞素材が再び不合格になる（実測）
2. **絶対値を取ってはならない。** 壁紙とは「ずらしても同じ」ことであり、
   正の相関である。**負の相関はむしろ逆**で、タイルが同一でないことを示す。
   絶対値を取ると、位相が半周期ずれた縞（相関 −0.888）を壁紙と誤判定する

### 規則模様は、周期がタイル幅を割り切ってはならない

畳・板張り・トタンの周期が 32px を割り切ると、**全タイルが同一になる。**
目地と位相を低周波ノイズで揺らし、さらに波の本数を
**32pxずらしの位相が半周期になる値**に合わせる。
1本ずらす（位相 1/8）では cos(2π/8)=0.71 で足りなかった。

## 17. ★★ 素材のためにパレットを足さない。**実行時のライトで解けないか先に問う**

水田の水面が「夜の海」に見えたとき、泥の色（低彩度の緑褐色）を
2〜3段足す案を出した。**却下された。理由が3つとも正しい。**

1. **ここで足すと歯止めがなくなる。**
   「この素材のために1色だけ」は、オブジェクト91点でもっと出てくる
2. **水面は Godot の 2Dライトと相性がいい。**
   第5節で「暗さと受光面は実行時に作る」と結論している。
   **反射や浅さは、素材に焼き込むより実行時に作るほうが正しい**
3. **F14 は夜が本番である。** 昼の泥の透け方より、夜の水面の
   不気味さのほうが作品にとって重要であり、青い水面はその用途に合う

> **素材が足りないと感じたら、パレットを足す前に問うこと。**
> **「これは実行時のライトで作れないか」**
>
> パレットを広げてよいのは、**構造的な欠落を実測で示せるときだけ**である
> （olive / warm を足したときは「色相45〜100度が0色」という実測があった。
> 第13節の後日談・第15節）。「この素材が思ったように出ない」は理由にならない。

同じ判断は、彩度の規約（`PALETTE.md`）とも整合する。
**歯止めは色数ではなく彩度**であり、そして**素材ごとの都合**でもない。

## 18. ★★★ 基準は、実物を置いてみてから凍結する

オブジェクトの判定基準7項目を、**実物を1点も作らないうちに提案し、承認された。**
その基準で deco 11点を判定したところ **2点しか通らなかった。**
そして**不合格9点の原因は、素材ではなく基準の側にあった。**

| 誤った基準 | 何が起きたか |
| --- | --- |
| **シルエットの太さ（1px収縮で70%以上）** | 3px の白線が 33%、4px の駐車枠が 50% で不合格。**実物を路面に置くと問題なく読めた。** 測りたかったのは「全体の細さ」ではなく「2px未満の突起」だった。収縮率は両者を区別できない |
| **地面との明度差20以上** | マンホール・グレーチング・側溝の蓋が不合格。**マンホールは実際にアスファルトと同じ暗さである。** 現実でも明度ではなく**形と縁**で見分ける。これは「地面に立つ物」の基準であり、地面に**付く** `ground_detail` には当てはまらない |
| **四辺の余白（トリム漏れ）** | 32x32 に内接する円（マンホール）は必ず四辺に余白を持つ。32x64 の中央に引いた4pxの線は面積の12%しか占めない。**どちらも正しい。**「余白＝トリム漏れ」という前提が誤りだった |

### なぜ気づけなかったか

**3つとも、実物を見て初めて分かった。** 机上では、どれも妥当に見えた。
根拠も添えてあった（見本の自販機の実測84%、納品済みタイルの明度帯26〜85）。
**根拠があることと、適用範囲が正しいことは別である。**

> **基準は、対象を数点作ってから凍結する。**
> 「先に基準を凍結し、途中で足さない」という規律（タイルセットで学んだ）は
> 正しいが、**凍結する前に実物で検証する工程が要る。**
> 少なくとも3点作り、判定を通し、目視と突き合わせてから凍結する。

### 訂正は「緩和」ではない

3件とも**基準を緩めたのではなく、誤って書いた基準を直した。**
訂正後、deco は 11/11、オブジェクトの試作は 5/5 が通り、
**目視でも問題が無かった。** 基準が実態に合っていなかっただけである。

**この区別を曖昧にしないこと。** 「素材が通らないから基準を下げる」のは
別の話であり、それは常に疑ってかかる。
