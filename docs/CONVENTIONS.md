# 規約

このリポジトリ全体で守る決めごと。プロジェクト固有の絵作りの方針は
各プロジェクトの `style/STYLE_GUIDE.md` に書く。

## 1. 命名規則

### プロジェクトID

- **小文字英数とハイフンのみ**（`^[a-z0-9][a-z0-9-]*$`）。40文字以内。
- ディレクトリ名（`projects/<project_id>/`）とログファイル名
  （`logs/generation_log.<project_id>.jsonl`）に使われるため、後から変更しにくい。
  最初に決めきること。
- 例: `iwato` / `moon-garden`

### 素材ファイル名

```
<category>_<subject>[_<variant>][_<index>].png
```

- 小文字英数とアンダースコアのみ。ハイフンは使わない（プロジェクトIDとの
  見分けをつけるため）。
- `index` は2桁ゼロ埋め（`01`, `02`, ...）。
- ノーマルマップは元素材名に `_n` を付ける（`bg_shrine_01_n.png`）。
  Godot の `CanvasTexture` に合わせた接尾辞。
- 例: `bg_shrine_night_01.png` / `tile_wood_floor.png` / `ui_dialog_frame.png`

### run_id

```
YYYYMMDD-HHMMSS-<4文字の乱数>
```

- 例: `20260904-143052-a1b2`
- `projects/<id>/_work/<run_id>/` と生成ログの `run_id` が1対1で対応する。
  この対応が「中間生成物を捨ててよい」根拠になるので崩さないこと。

### ブランチ名

```
<type>/<短い説明>
```

- 例: `chore/repo-structure` / `feat/iwato-palette` / `fix/postprocess-alpha`

## 2. ディレクトリ規約

### 共有するもの / 分けるもの

| 対象 | 置き場所 |
| --- | --- |
| ツール群 | `tools/`（共有） |
| 規約・手順書 | `docs/`（共有） |
| 生成ログ | `logs/`（共有。ファイルはプロジェクト別） |
| パレット / スタイル / 要件 / 素材 / 参考画像 / 進捗 | `projects/<project_id>/`（プロジェクト別） |

**ツール側にプロジェクト名やプロジェクト固有の値を書かないこと。**
解像度・タイルサイズ・色数は `projects/<id>/project.yaml` にのみ書き、
ツールには `--project <project_id>` だけを渡す。

### Git に入れるもの / 入れないもの

| パス | Git | LFS | 理由 |
| --- | --- | --- | --- |
| `projects/*/assets/**/*.png` | ○ | **○** | 完成品。これだけが LFS 対象。**再現性の唯一の担保でもある** |
| `projects/*/project.yaml` `style/` `palettes/` `requirements/` | ○ | × | テキスト |
| `logs/generation_log.*.jsonl` | ○ | × | テキスト。差分を追いたい |
| `projects/*/refs/` | **×** | × | 第三者の著作物 |
| `projects/*/_work/` | **×** | × | 中間生成物。LFS 枯渇を防ぐ |
| `.env` `.env.*` | **×** | × | 機密情報 |

### `refs/` — 参考画像

- 既存商用ゲームのスクリーンショット等、**第三者の著作物**を置く。
- `.gitignore` の `**/refs/` で**全階層を例外なく除外**している。
- **`!` による再包含の例外を作らないこと。** 否定パターンを1つ入れると
  「除外されているはず」という思い込みが生まれ、事故の温床になる。
  また Git はディレクトリ自体を除外した場合その中の否定パターンを評価しないため、
  意図通りに効かない。
- `refs/` は Git 上に一切存在しない。クローンした人の手元には作られないので、
  `tools/new_project.py` が空ディレクトリとして明示的に作る。

### `_work/` — 中間生成物

- API の生出力を `projects/<id>/_work/<run_id>/` に置く。
- `.gitignore` の `**/_work/` で全階層を例外なく除外している。
- **ログを書き終えたら削除してよい。** 詳細は
  [README の「中間生成物を残さない方針」](../README.md#中間生成物を残さない方針)。

### 除外パターンを `**/` にしている理由

`projects/*/refs/` のような限定パターンでは `templates/project/refs/` に効かず、
将来 `projects/` 以外の場所に置かれたものも取りこぼす。
`**/refs/` なら**どの階層に現れても確実に除外される**。
除外の確実性を、パターンの精密さより優先している。

## 3. コミット規約

[Conventional Commits](https://www.conventionalcommits.org/) 形式。**本文は日本語でよい。**

```
<type>(<scope>): <要約>

<本文>
```

| type | 用途 |
| --- | --- |
| `feat` | 機能追加、新規素材の追加 |
| `fix` | 不具合修正、素材の修正 |
| `chore` | 構成・設定・依存関係 |
| `docs` | ドキュメントのみ |
| `refactor` | 挙動を変えない整理 |

- `scope` にはプロジェクトID かツール名を書く（`feat(iwato):` `fix(postprocess):`）。
- **`main` への直接コミットは禁止。** ブランチを切って PR を出すこと。
- **APIキーをコミットメッセージに書かないこと。**

### PR 本文

以下の4項目を必ず含める。

- 概要
- 変更点
- 確認方法
- 未対応・既知の課題

## 4. 素材の品質基準

`tools/validate_assets.py` の検査基準。判定値は `project.yaml` から読む。

### パレット適合

- 使用色が `palette.max_colors` 以下であること。
- `palette.file` が指定されている場合、**そのパレットに含まれる色のみ**を使うこと。
- パレット外の色が1色でもあれば不合格。

### グリッド

- 画像の幅・高さが `canvas.tile_size` の倍数であること（UI とアイコンを除く）。
- タイルセットはタイル境界がずれていないこと。
- 背景は `canvas.base_resolution` を基準とし、その整数倍または
  タイル単位の切り出しであること。

### 透明度

- **半透明画素を含まないこと。** アルファ値は 0 か 255 のみを許容する。
- 中間のアルファ値はエンジン側のフィルタと相性が悪く、ドット絵が滲む原因になる。

### アンチエイリアス

- **輪郭にアンチエイリアスをかけないこと。** 生成物に含まれる場合は
  `tools/postprocess.py` で除去してから完成品とする。
- 意図的な階調表現はディザリングで行う（プロジェクトごとの可否は
  `style/STYLE_GUIDE.md` に定める）。

### 出力設定

`project.yaml` の `output` は**エンジン側のインポート設定と一致させること。**

| 項目 | ドット絵での値 |
| --- | --- |
| `filter` | `nearest` |
| `mipmaps` | `false` |
| `compression` | `none` |

## 5. 生成ログの規約

- 置き場所は `logs/generation_log.<project_id>.jsonl`。1行1レコード、**追記のみ。**
- **生成したものは採否にかかわらず全て記録する。** 不採用のレコードには
  `adopted: false` と `reject_reason`（1行）を必ず書く。
- 記録項目は `tools/lib/genlog.py` の `FIELDS` を正典とする。
- `seed` は指定した値を記録する。**同一シードでも同一画像にはならない**ため、
  これは復元用ではなく条件記録である。未指定なら `null` と理由を `seed_note` に書く。
- コストは推定値ではなく**レスポンスの実測値**を記録する。従量課金なら
  `usage.usd`、回数制なら `billing_usage.generations` に載る。両方を記録する。
- **APIキーおよびそれに類する値を書かないこと。** `genlog.append()` が
  キー名（`api_key` `token` `secret` 等）で機械的に弾く。
- ログを消さないこと。ただし**ログは画像の復元手段ではない。**
  **seed は存在するが、同一シードでも同一画像にならないことを実測で確認した。**
  中間生成物を捨てる根拠は「完成品が Git LFS にあること」である。
  ログを残す理由はコスト管理・引き直しの条件保存・不採用理由の蓄積の3つで、
  とくに**不採用理由は作り直せない情報**である。

## 6. プロジェクト間での素材の流用

**共有ディレクトリは作らない。コピーして取り込み、由来を記録する。**

素材はパレット・タイルサイズ・解像度がプロジェクト固有であり、そのまま
流用できることはほとんどない。流用とは実質「別プロジェクトの素材を、
こちらのパレットで焼き直す」ことになる。それは共有ではなくコピー＋再加工である。

手順:

1. 流用元の素材を `projects/<dst>/assets/<category>/` にコピーする。
2. `tools/postprocess.py --project <dst>` で取り込み先のパレット・グリッドに
   合わせて焼き直す。
3. 生成ログに1行追記する。新規生成でなくとも来歴は必ず残す。

```json
{"project_id": "<dst>", "source": {"type": "derived", "from_project": "<src>", "from_asset": "assets/tilesets/tile_stone_moss.png"}}
```

これにより各プロジェクトは自己完結し、ゲーム本体リポジトリへの取り込みも
`projects/<id>/assets/` を丸ごと持っていくだけで済む。

流用が頻発するようなら、その時点で共有ディレクトリの新設を検討する。
**現時点では作らない。**
